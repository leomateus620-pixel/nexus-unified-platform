# Nexus agent integrations

## Prepared surface

- OAuth-protected `/mcp` generated by the SDK; consent at `/.lovable/oauth/consent`.
- `list_organizations`, `search_products` and `list_proposals` are bounded read-only queries.
- Catalog and commercial access check verified caller membership and current module roles, then use caller-scoped RLS. Costs and revision parameters are excluded.
- The proposal list registers `list_visible_proposals` only while mounted, reading its current filtered collection through WebMCP. Telemetry includes static name, outcome and duration only.
- OAuth login, signup confirmation and managed Google login preserve the validated consent return path. No copied app-session tokens are an integration mechanism.

## Verified in preview (2026-10-30)

- Manifest extraction generated all three remote tools.
- Automatic build/typecheck: OK.
- 27 focused tests: return-path security, organization/module checks, fail-closed lookup and existing navigation permissions.
- Browser: unauthenticated MCP returns 401; signed-out consent redirects to login preserving authorization ID; missing/invalid authorization renders a readable error; authenticated proposal list loads.
- Managed OAuth server enabled with dynamic registration. Existing email/password and Google integration preserved. Read-only provider diagnostics confirm canonical custom domain and wildcard redirect coverage for consent.

- The verification browser does not expose WebMCP discovery; runtime catalog discovery there remains unverified. Normal proposal UI was verified.
- No new application data, orders, schema, role grants or RLS policies were created.
